# Dependencies

Every pinned dependency version in this repository lives in one catalog:
[`deps/versions.toml`](../deps/versions.toml). A dependency bump changes
exactly one value there. `mise run deps-check` fails when any consumer in the
repository disagrees with the catalog.

## Purpose

The repo pins dozens of versions across mise configs, Kubernetes manifests,
CI workflows, airgap scripts, and documentation. Before the catalog these
were independent literals that drifted silently. The catalog makes each
logical dependency a single named key and validates (or generates) every
consumer from it.

## Update procedure

1. Edit the value in `deps/versions.toml`.
2. Fix any slot failures reported by `mise run deps-check`. A bump that
   forgets a consumer makes the old-value pattern match zero times; a
   consumer edit that forgets the catalog fails the same way.
3. Run `mise run validate`, then open a PR.

Generated consumers (`zarf.yaml`, `images.txt`, airgap scripts) are wired in
follow-up PRs; until they land, every consumer is updated by hand and held to
the catalog by slots.

## Intentional differences

These are separate catalog keys on purpose, not drift:

- `gh_checkout_airgap` and `gh_checkout_renovate_test` (7.0.1) vs
  `gh_checkout_validate` (5): action versions are upgraded per workflow or
  independently scoped job, not repo-wide.
- `k8s_mgmt_node` (1.36.1, kind management cluster) vs
  `k8s_workload_node` (1.35.0, CAPD workload nodes) vs `k8s_eks`
  (1.34.6, EKS workload clusters): three profiles upgrade independently.
- ACK `ack_iam` chart 1.7.2 is shared by the mgmt and workload trees: one
  logical dependency, two slots.
- `eks_addon_kube_proxy` happens to track `k8s_eks` today but has its own
  key so an EKS bump does not silently bump kube-proxy.
- `flux2`, `sops`, `age`, `aws_cli` are recorded as `latest`; pinning them
  is a separate decision.

## Exclusions

Not dependencies; deliberately absent from the catalog:

- `version:` fields inside `*.sops.yaml` (SOPS file format version).
- Node-baked images inside `kindest/node` (kube-apiserver, etcd, coredns,
  local-path-provisioner): derived from the node image; listed in
  `airgap/images.txt` for inventory only.
- `apiVersion` strings and Helm chart `appVersion` values.
- Zarf package `metadata.version: 0.1.0` (package release version).

## Validation vs generation, per consumer class

| Consumer class | Treatment |
|---|---|
| mise tool pins | Slot validation (`mise.toml`, `mise.aws.toml`) |
| Generated files (`zarf.yaml`, `images.txt`, airgap scripts) | Rendered from or sourced from the catalog; drift check compares output |
| Flux-synced manifests | Validation-only slots: YAML cannot read external files at reconcile time |
| GitHub Actions workflows | Validation-only slots: workflows cannot include external files |

## Forbid matcher scope

The `--forbid` literal match is segment-based: a version matches only at
dot boundaries, so `10.83.0` never matches `0.83.0`. Hyphen-suffixed
variants like `0.83.0-rc1` DO match the base key and fail loudly; when
pinning a prerelease, give it its own catalog key.
